# GrowthHub M4 切片一开发记录

本轮推进周计划与事实复盘，M3 七天真实试用保持未完成状态。

## 交付

- /weekly 周导航、周主题与时间预算、编辑归档恢复。
- 按真实日期分别统计日志实际分钟、任务预计分钟、排期完成状态和本周完成时间，不相加重复计算。
- 手工复盘草稿、真实来源快照、原文保存、失效拦截、刷新保留已保存文字、确认后只读与重复确认重试。
- 版本冲突保留未保存的复盘文字，可显式载入服务端版本。
- Flyway V3，JSON 导出 v2 增加周计划/复盘，排除内部哈希。

## 为什么这样设计

任务排期周与实际完成周可能不同，必须分别展示。没有日志不能推断没有学习，任务完成不等于能力认证。复盘冻结原文后再确认，来源更新要重新核对，确认历史不能随之后编辑改变。先让无模型的流程可用，再加入 AI 草稿。

## 如何证明

Maven verify：10 项 JUnit；42 项真实 PostgreSQL/API 测试；8 项 Chromium 验收通过。跨年周、上海完成时间边界、取消任务、来源变化、并发确认、旧版本、导出和编辑文字保留都有验收。强制中断恢复和无密钥拦截通过。

隔离测试库恢复到独立空库 growthhub_restore_m4_20261015_080351，十张业务表和 Flyway 历史逐行一致，包括周计划 3 条、周复盘 5 条；非空库恢复保护通过。开发库升级前已备份，原八张业务表哈希一致，两张新表无测试数据。

## 后续计划

1. 独立成果记录：标题、类型、日期、链接与目标/任务关联，保留原日志的成果文本。
2. 显式周任务分配与跨周调整规则；本轮按任务排期日期归周。
3. 周复盘 AI 草稿：独立的周输出契约和真实来源证据，复用现有多提供商和异步机制，继续人工确认。
4. 配置真实模型后小规模联调，并完成七天真实试用；不把模拟测试视为试用完成。

本轮未新增系统软件和依赖，未部署公网。代码尚未提交或推送。完整接口与边界见 docs/weekly-workspace.md。
